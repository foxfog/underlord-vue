# Студия спрайтов и риггинга (Live2D-Lite)

Документация интерактивной среды риггинга, тестирования спрайтов и настройки анимаций персонажей (`CharacterSpriteTesterView.vue` и `useCharacterRigStudio.js`).

---

## 1. Назначение и доступ

Среда предназначена для:
1. Визуального разбора и сборки составных частей тела персонажей (дробление от одиночного спрайта до сложного скелета: голова, плечи, предплечья, кисти, живот).
2. Настройки точек вращения (пивотов), смещений (`offset.x`, `offset.y`) и порядка слоев (`zindex`).
3. Управления направлением взгляда с помощью интерактивного 2D-джойстика (стикера) с пресетами сцен.
4. Переключения эмоций с подменой спрайтов для лица и тела.
5. Прямого позирования суставов и тестирования анимаций (махание рукой, кашель, дыхание, дрожь, кивок).
6. Экспорта шагов анимации в формате сценария визуальной новеллы (`part-animate`).
7. Настройки роста (`size` / `scale`) с линейкой в сантиметрах и видом со спины (`char-back`).

Доступен в главном меню тестов по маршруту: `/test/character-sprites`.

---

## 2. Базовый шаблон персонажа (`default`)

Персонаж с ID `default` расположен в:
* Данные: `src/renderer/public/data/characters/default/` (`values.json`, `body.json`, `equipment.json`).
* Спрайты: `src/renderer/public/images/sprites/characters/default/`.

Папка `images/sprites/characters/default/` также служит **глобальным фоллбеком**: если у персонажа нет индивидуальных спрайтов для частей тела или изометрии, движок автоматически использует графику из `default`.

---

## 3. Дробление тела (Decomposition) и Дерево иерархии (Hierarchy Tree)

* При наличии единого спрайта `body` доступна кнопка «Разделить тело на части», автоматически создающая `head`, `arm_left`, `arm_right`.
* Руки можно дробить дальше на звенья:
  * `arm_left` (плечо) $\to$ `arm2_left` (предплечье от локтя) $\to$ `arm3_left` (ладонь/кисть).
* Каждая часть привязывается к родителю через поле `"parent"`.
* **Визуализация иерархии в интерфейсе студии**:
  * Вкладка **«Дерево частей тела (Hierarchy)»** отображает древовидный список со строгой рекурсивной сортировкой (`body` $\to$ `neck` $\to$ `head`, `arm_left` $\to$ `arm_left2` $\to$ `arm_left3`).
  * Каждый элемент имеет динамический отступ глубины (`0.45 + depth * 0.95em`), ветки (`⭐` корень, `├─` L1, `│ └─` L2, `│   └─` L3) и бейдж уровня вложенности (`L0`, `L1`, `L2`, `L3`).
  * При выборе детали подсвечиваются все её предки (`__is-ancestor`), визуализируя прямую кинематическую цепь до корня.
  * В карточке «Инспектор части» и вверху холста сцены отображаются интерактивные **Хлебные крошки (Breadcrumbs)**: `🧬 body › arm_left › arm_left2`, позволяющие мгновенно переключаться между звеньями цепи.

## 4. Направление взгляда (2D Стикер)

Компонент `EyeDirectionPad.vue`:
* Режимы: **Связанный** (оба глаза синхронно) и **Раздельный** (левый и правый глаз по отдельности).
* Координаты $X, Y \in [-1, 1]$ транслируются в смещение глазных слоев / зрачков.
* Пресеты для быстрых сценарных указаний:
  * `center` / `camera`: (0, 0)
  * `roll_eyes`: закатывание глаз вверх
  * `ahegao`: расхождение зрачков вверх
  * `squint`: косоглазие к переносице
  * `avert`: отведение взгляда в сторону

## 5. Анимации и экспорт в VN JSON

Встроенная библиотека пресетов:
* **Махание рукой (`wave_hand`)**: плечо поднимается до $-55^\circ$, предплечье колеблется $\pm 28^\circ$ с частотой ~6 Гц, ладонь подрагивает.
* **Кашель / Чих (`cough`)**: двойной толчок головы со смещением `translate(-2.5%, 3%)` (как в CSS `@keyframes coughHead` из интро) и наклоном шеи до $-8^\circ$ (`coughNeck`) без раскачивания и тряски тела `body`.
* **Дыхание (`breathing`)**: плавный ритмичный подъем груди и плеч.
* **Дрожь (`tremble`)**: высокочастотный джиттер.
* **Кивок (`nod`)**: плавный наклон головы вперед в знак согласия.
* **Отрицание (`head_shake`)**: покачивание головы из стороны в сторону.

Кнопка **«Экспорт шага VN JSON»** копирует готовый блок сценария:
```json
{
  "type": "part-animate",
  "character": "default",
  "part": "arm2_left",
  "styles": {
    "transform": "rotate(25deg)",
    "transition": "transform 0.4s ease-in-out"
  },
  "duration": 0.4
}
```
которое можно напрямую вставлять в `scenes.json`.

## 6. Управление холстом: Панорамирование (Drag-to-pan) и Масштабирование

* **Перетаскивание сцены**: зажатие левой, средней или правой кнопки мыши (или touch-жест) в области холста свободно перемещает сцену в любом направлении (курсор `grab` / `grabbing`).
* **Защита кликов**: при перетаскивании сцены поверх персонажа смена выбранной части тела блокируется (часть выбирается только обычным щелчком без смещения).
* **Колесико мыши (Scroll Wheel)**: адаптивный зум холста от 20% до 1000% (шаг 0.1 до 200%, 0.25 до 500%, 0.5 до 1000%).
* **Кнопки управления**:
  * `🎯 Центр` — центрирует персонажа на экране, возвращая координаты смещения в (0, 0).
  * `+` / `-` — пошаговый зум до 1000%.
  * `Сброс` — возвращает масштаб в 100% и центрирует холст.

## 7. Иерархия, Центрирование и Вложенный 2D Риггинг (Nested Visual Rig)

1. **Точка опоры (Anchor Point) и Вращение — Строго Центр (50%, 50%)**:
   * Для всех частей тела точка вращения по умолчанию строго центрирована: `x: 50%, y: 50%`.
   * Повороты деталей (`rotate(...)`) происходят вокруг их геометрического центра спрайта, а не по низу (шея) или верху (плечи).
   * В инспекторе части доступна быстрая кнопка `🎯 В центр` для сброса точки вращения в (50%, 50%).
   * **Движок рендеринга (Canvas 2D Engine vs Legacy DOM)**:
     * В шапке студии доступен переключатель **`⚡ Canvas` / `🧱 DOM`**.
     * **Режим Canvas 2D (`CharacterCanvas.vue` + `characterRigRenderer.js`)**:
       * Вычисляет локальные и мировые аффинные матрицы 2D ($2 \times 3$) на основе Scene Graph.
       * Корневая часть (`body`) центрируется по оси X сцены (`width / 2`) и подошвами ставится точно на линию уровня земли 0 см (`height - rootHeight / 2`).
       * **Буфер перелива (Bleed Margins)**: холст студии имеет запас отрисовки ниже 0 см (`bottom: -10em`, до -60 см), выше 240 см (`top: -3.5em`) и по бокам (`left/right: -8em`), благодаря чему носки стоп, каблуки или наклонные позы, уходящие ниже уровня земли 0 см, **не обрезаются и остаются полностью видимыми**.
       * Линия 0 см («Земля / Стопы») накладывается поверх холста для точной подгонки пятки, а шкала линейки включает отрицательные отметки (`-30 см`).
       * Поддерживает аппаратное масштабирование экранов (HiDPI / Windows DPI Scaling): трансформации умножаются на `dpr` в `ctx.setTransform(a*dpr, b*dpr, c*dpr, d*dpr, e*dpr, f*dpr)`, сохраняя четкость пикселей и совпадение координат с оверлеями сцены.
       * Точка крепления дочернего центра относительно центра родителя:
         $\text{attachX} = \text{parentWidth} \cdot \frac{\text{offset.x}}{200}$, $\text{attachY} = \text{parentHeight} \cdot \frac{\text{offset.y}}{200}$.
       * Вращение происходит строго вокруг собственного центра дочерней детали, а при повороте родителя дочерний центр поворачивается по дуге вокруг родительского центра.
       * Размеры спрайтов для моддинга могут быть любыми — центровка не сбивается и детали не прыгают.
       * Z-Index полностью отвязан от иерархии костей (нет ловушки CSS Stacking Context).
     * **Режим DOM (Legacy Fallback)**:
       * Сохранен для обратной совместимости через CSS `margin: auto; right: 0; bottom: 0; left: offset.x%; top: offset.y%;`.
   * При `offset: { x: 0, y: 0 }` деталь крепится **строго по горизонтальному и вертикальному центру родителя**.
   * Значения `offset.x` и `offset.y` задают процентный сдвиг детали именно от центра родителя.
2. **Пропорциональное масштабирование высоты**:
   * Для корня (`body`) фиксируется натуральная высота спрайта `--charbodyspriteH`.
   * Для каждой дочерней части замеряется её `--charspriteH` (`naturalHeight` картинки) и вычисляется размер:
     `height: calc(var(--charspriteH) / var(--charbodyspriteH) * var(--char-height))`
3. **Рекурсивная вложенность любой глубины**:
   * Компонент `RigPartNode` рекурсивно рендерит дочерние ветви без ограничения уровней (например, цепочка MC из 4 уровней: `body -> arm_left -> arm_left2 -> arm_left3`).
4. **Визуализация центра спрайта и фильтр частей (`showSpriteCenter`)**:
   * В верхней панели оверлеев сцены доступна кнопка `🎯 Центр спрайта`.
   * **Тонкое перекрестие поверх всех слоев (`.stage-sprite-centers-layer` / `.rig-part-crosshair`)**:
     * Отображается аккуратным перекрестием (`+`) толщиной ровно 1 пиксель (`border: 1px solid #10b981`), не загромождая арт персонажа.
     * Рендерится на верхнем уровне холста сцены (`stage-frame`), благодаря чему **гарантированно находится поверх всех частей тела** (не перекрывается телом, одеждой или частями с отрицательным z-index вроде `arm_right`).
     * Не наследует локальные CSS-трансформации частей (повороты `rotate`, отражение `scaleX(-1)` при смене ориентации) и компенсирует масштаб сцены (`scale(1 / stageZoom)`), поэтому маркеры **никогда не деформируются** и всегда сохраняют вертикально-горизонтальную форму и толщину в 1px.
     * При наведении подсвечивается золотым, при выборе части — бирюзовым цветом (`#06b6d4`), по клику выбирает деталь в инспекторе рига.
   * **Боковая панель фильтрации (`⚙️ Части`)**: при включенном режиме рядом появляется кнопка вызова боковой панели.
   * Панель позволяет чекбоксами точно выбирать, у каких именно частей тела отображать перекрестие центра, а также содержит быстрые кнопки «✓ Все», «✕ Снять», «⇄ Инверт». Закрывается по кнопке `✕` или клавише `Escape`.

## 8. Канонический рост, скейл визуала и целевая линия (Visual Scale Fitting)

1. **Разделение понятий**:
   * **Биологический рост (`height`, см)**: канонический параметр персонажа, задаваемый во вкладке «Биометрия» в Редакторе данных (`values.json`).
   * **Скейл визуала (`size` / `scale`)**: технический коэффициент масштабирования арт-ассетов (с точностью до тысячных, например `1.045`). Скейл служит инструментом подгонки спрайта под его реальный рост и **не перезаписывает** биологический рост `height`.
2. **Золотая линия целевого роста (`target-height-guide`)**:
   * На холсте студии отображается горизонтальная направляющая линия с бейджем `🎯 Целевой рост: {height} см`.
   * Положение линии зафиксировано точно на высоте персонажа (`bottom: (height / 240) * 100%`).
   * Разработчик может регулировать скейл визуала, пока макушка спрайта не коснется этой золотой линии.
3. **Управление скейлом во вкладке «Риг и части» (Tab 1)**:
   * **Быстрая сводная полоса (Quick Scale Bar)**: размещена вверху вкладки, показывает целевой рост `🎯 {height} см`, текущий коэффициент скейла визуала, кнопки `±0.01`, сброс `1.0` и быстрое сохранение.
   * **В инспекторе части при выборе `body`**:
     * Полноценный блок **«Скейл визуала (Scale)»** расположен непосредственно между свойствами прозрачности и смещения. С бейджем `🎯 Цель: {height} см`.
     * Слайдер и поле точного ввода (`min="0.2" max="3.0" step="0.001"`).
     * 7 кнопок микро-степперов: `-0.05`, `-0.01`, `-0.001`, `1.000`, `+0.001`, `+0.01`, `+0.05`.
     * Кнопка прямого сохранения: `💾 Сохранить скейл в values.json`.
   * **В инспекторе дочерних деталей (руки, голова, торс и др.)**:
     * Блок **«Масштаб детали (Part Scale)»** с локальным скейлингом звена, кнопкой сброса `🔄 1.0` и быстрыми степперами. Значение сохраняется в свойстве `scale` файла `body.json`.
4. **Синхронизация сохранения**:
   * При нажатии `💾 Сохранить body.json` студия автоматически записывает не только структуру частей тела, но и актуальный скейл модели (`size`, `scale`) в `values.json`, предотвращая рассинхронизацию файлов.
5. **Бесшовная интеграция с Редактором данных**:
   * В шапке студии и в карточке канонического роста размещены кнопки быстрого перехода: `📝 Редактор данных` и `✏️ В биометрию` $\to$ `/editor?tab=characters&id={id}&subtab=biometrics`.
   * В Редакторе данных в панели подвкладок добавлена кнопка `🎭 Студия спрайтов →`, а во вкладке биометрии — быстрый баннер перехода $\to$ `/test/character-sprites?character={id}`.

## 9. Пространственные направляющие, Canvas-рендерер и калибровка точки стояния (Root Offset)

Для идеальной посадки персонажей на сцены новеллы и исключения визуального парения/проваливания в студии реализована координатная сетка привязки стоп:

1. **Подсвеченная нулевая отметка (0 см) и линия пола (`ground-baseline-guide`)**:
   * Отметка `0 см` на линейке подсвечена неоновым голубым цветом (`.__zero`).
   * Через всю сцену проведена направляющая линия уровня пола с бейджем `⚓ 0 см (Земля / Стопы)`.
   * Реальная точка стояния персонажа находится строго под его пятками/подошвами, а не под прозрачным нижним краем PNG-файла.
2. **Поля запаса рендеринга (Canvas Bleed Margins) и отрицательная шкала**:
   * Для отрисовки носков обуви или деталей, опускающихся ниже уровня пятки/земли (`0 см`), холст сцены расширен полями вылета (`bleed.bottom = 10em`, `bleed.top = 3.5em`, по бокам `8em`).
   * Линейка расширена вниз до `-30 см` (отрицательная отметка `.__negative`), что исключает нежелательное отсечение спрайтов за пределами нулевой линии.
3. **Центральная вертикальная ось сцены (`center-axis-guide`, Ось X: 0)**:
   * Фиолетовая направляющая линия с бейджем `↔️ Ось X: 0` визуализирует горизонтальный центр сцены новеллы.
   * Позволяет сбалансировать центр тяжести и осанку спрайта по вертикали.
3. **Корневое смещение аватара (`root_offset`)**:
   * **Смещение Y**: опускает или приподнимает весь спрайт персонажа, приводя подошвы ровно к линии 0 см.
   * **Смещение X**: центрирует персонажа по горизонтальной оси сцены.
   * Панель управления во вкладке «Вид и Рост» включает слайдеры, числовые поля и быстрые степперы (`-1%`, `-0.2%`, `-0.05%`, `0%`, `+0.05%`, `+0.2%`, `+1%`).
4. **Хранение и отображение в игре**:
   * Значения сохраняются в `values.json` в поле `root_offset: { x, y }` и дублируются в `body.json` в свойствах корня `body.offset`.
   * В игровом компоненте `Character.vue` смещение применяется через `style.translate = `${ro.x}% ${-ro.y}%``, гарантируя идентичность позиционирования в диалогах и сценах новеллы.

## 10. Редактор анимаций (Animation Studio & Timeline)

Полноценная среда создания, редактирования и воспроизведения покадровых и процедурных анимаций риггинга (`CharacterAnimationEditorModal.vue` + `useCharacterRigStudio.js`).

### 1. Доступ и управление в студии
* В боковой панели студии (вкладка «Позирование и Анимации») доступна библиотека анимаций с фильтрацией по группам.
* Быстрые кнопки:
  * `➕ Создать` — открывает модальное окно создания новой анимации.
  * `✏️` на карточке — переход в редактор существующей анимации.
  * `📋` — мгновенное дублирование анимации со всеми треками и кадрами.
  * `🗑️` — удаление кастомной анимации (удаление базовых пресетов заблокировано).
  * `⏹ Стоп` / `🔄 Сбросить позу` — сброс всех углов, смещений и скейлов.
* **Интерфейс редактора (Left Dock Drawer)**:
  * Панель редактора анимаций прикреплена к **левому краю экрана** (`width: 33em`, `max-width: 45%`), не перекрывая центральный холст с персонажем.
  * Фон и подложка прозрачны (`backdrop-filter: none; background: transparent; pointer-events: none;`), благодаря чему персонаж остаётся кристально чётким без размытия, а холст доступен для панорамирования и масштабирования колёсиком мыши прямо во время редактирования кадров.
  * Кнопка сворачивания `◀` / `▶` в шапке редактора временно сворачивает панель в узкую вертикальную планку шириной `3.6em`, полностью освобождая обзор спрайта без закрытия сессии редактирования.

### 2. Мульти-трансформации деталей
Каждый ключевой кадр трека поддерживает одновременное изменение следующих параметров:
* **Вращение (`rotate` / `rot`)**: расширенный диапазон слайдера $\pm 720^\circ$ (с возможностью ввода любых углов числовым инпутом).
* **Смещение (`translateX`, `translateY`)**: расширенный диапазон от $-500\%$ до $+500\%$ (ранее было $\pm 100\%$), что позволяет полностью уводить и скрывать детали (например, глаза/зрачки за $-300\%$).
* **Масштаб (`scale`)**: скейл звена (от $0.1\times$ до $3.0\times$) с быстрыми пресетами для зрачков: $0.5\times$ (подозрение/прищур), $1.0\times$ (норма), $1.4\times$ (удивление/шок).
* **Поворот по горизонтали (Rotate Y / Yaw)**: диапазон от $-85^\circ$ до $+85^\circ$, перспективно сужает зрачки/детали по горизонтали на $\cos(\text{angle})$ при взгляде вбок.
* **Поворот по вертикали (Rotate X / Pitch)**: диапазон от $-85^\circ$ до $+85^\circ$, перспективно сужает зрачки/детали по вертикали на $\cos(\text{angle})$ при взгляде вверх/вниз.
* **Кастомные CSS-стили (`customCss`)**: любые дополнительные свойства (например `filter: brightness(1.2)`, `opacity: 0.8`).
* **Подмена спрайта (`animatedSprites`)**: выбор альтернативного PNG-спрайта для конкретной части на данном кадре (например, смена раскрытой ладони на кулак или полуприкрытый глаз).

### 3. Таргетинг: Одиночная деталь vs Иерархический каскад
Для каждого трека настраивается `targetMode`:
* **Только деталь (`single`)**: трансформация действует исключительно на выбранную часть тела.
* **Иерархически ко всем потомкам (`hierarchy`)**: трансформация каскадно передаётся выбранной детали и рекурсивно всем её дочерним звеньям (вычисляется через `getDescendants(partName)`). Например, наклон плеча сдвинет всё предплечье и кисть, если они не имеют локальных смещений.

### 4. Режимы воспроизведения и интерполяция
* **Повторяемость (`repeat`)**:
  * `loop` — циклическое повторение.
  * `once` — однократное воспроизведение с автоматической остановкой на последнем кадре.
  * `pingpong` — движение вперёд и затем назад (маятник).
  * `count` — ограниченное число циклов (`repeatCount`).
* **Кривые сглаживания (`easing`)**: `ease-in-out` (плавное), `linear` (равномерное), `ease-in` (разгон), `ease-out` (замедление), `step` (мгновенный скачок).

### 5. Процедурный режим (Математические формулы)
Переключатель режима анимации позволяет писать процедурные формулы для тика анимации на чистом JavaScript в безопасной песочнице `new Function`:
* **Доступные переменные**: `time` (текущее время в секундах), `progress` ($0..1$), `cycle`, `duration`, `parts`, `getDescendants`.
* **Математические функции**: `sin`, `cos`, `tan`, `PI`, `abs`, `min`, `max`, `round`, `floor`, `random`.
* **Пример формулы**:
  ```javascript
  const wave = sin(progress * 2 * PI);
  return {
    head: { rot: wave * 12, x: -2, y: wave * 3 },
    arm_left: { rot: cos(progress * 2 * PI) * 20 }
  };
  ```

### 6. Сохранение данных (`animations.json`)
Кастомные анимации персонажа сохраняются в файл:
`src/renderer/public/data/characters/[characterId]/animations.json`
Файл автоматически загружается при выборе персонажа в студии.

### 7. Вызов анимаций в сценарии визуальной новеллы (`scenes.json`)
Созданные анимации можно напрямую вызывать в сюжетных скриптах новеллы:
```json
{
  "type": "animate",
  "character": "mc",
  "animation": "cough",
  "duration": 1.3
}
```
Также поддерживаются алиасы `"type": "character-animate"` и `"type": "play-animation"`.
В модальном окне редактора анимаций кнопка **«📋 Скопировать шаг для истории»** автоматически формирует и копирует готовый JSON-шаг в буфер обмена.

## 11. Изометрическая студия спрайтов и риггинга (Isometric Rig Studio)

Полноценный режим редактирования, позирования и анимации изометрических спрайтов персонажей (`viewMode = 'isometric'`).

### 1. Переключение режимов: 2D Новелла vs 2.5D Изометрия
* В шапке студии размещён селектор режима отображения:
  * **2D Новелла (`vn`)**: классический портретный Live2D-Lite риг персонажа в полный рост.
  * **2.5D Изометрия (`isometric`)**: пиксельный спрайт для тактической изометрической карты и боёвки.
* При переключении режима состояние 2D рига (части тела, кастомные анимации, оверрайды эмоций, масштаб) сохраняется в памяти, и студия мгновенно активирует изометрический контур.

### 2. Принцип Pixel-Art масштабирования (Strict 1:1, без биометрического скейлинга)
* **Запрет масштабирования визуала**: изометрическая графика выполнена в пиксель-арте. Коэффициенты `size` / `scale` из биометрии (`values.json`) **строго игнорируются** и зафиксированы на `1.000x`.
* **Натуральные пропорции**: видимый размер и рост персонажа в изометрии определяются исключительно реальными габаритами самих пиксельных спрайтов (в пикселях файла).
* **Стили рендеринга**: для всех изометрических деталей гарантированно включены свойства `image-rendering: pixelated; image-rendering: crisp-edges;`, исключающие любое размытие или фильтрацию при зуме холста.
* **Защита сохранения**: сохранение скейла в `values.json` заблокировано в изометрическом режиме во избежание порчи параметров 2D-новеллы.

### 3. Структура изометрических данных и автосохранение
* **Изометрический скелет (`iso_body.json`)**:
  * Путь: `src/renderer/public/data/characters/[characterId]/iso_body.json`.
  * При отсутствии файла студия автоматически ищет одиночный спрайт `isometric/char.png`, либо составные части `isometric/head.png`, `isometric/arm_left.png`, `isometric/arm_right.png`.
  * Кнопка «Разделить тело на части» в изометрии автоматически инициализирует базовый скелет с изометрическими частями.
  * Кнопка сохранения в шапке динамически меняется на **«💾 Сохранить iso_body.json»**.
* **Изометрические анимации (`iso_animations.json`)**:
  * Путь: `src/renderer/public/data/characters/[characterId]/iso_animations.json`.
  * Встроенная библиотека пресетов для изометрии:
    * `iso_idle` — плавное дыхание и покачивание плеч в стойке.
    * `iso_walk` — шагающий цикл конечностей с подъемом коленей и компенсацией торса.
    * `iso_attack` — замах и рубящий удар рукой/оружием с уходом в перспективу.
    * `iso_hit` — отдача и толчок тела назад при получении урона.
* **Подмена эмоций в изометрии (`isoEmotionOverrides`)**:
  * Позволяет настраивать оверрайды спрайтов лица/головы для изометрического ракурса независимо от портретов 2D-новеллы.

### 4. Изометрическая проекция вращения суставов (Trapezoid & Dimetric Projection)
В изометрической 2:1 проекции (сетка $64 \times 32$, угол наклона $\approx 26.565^\circ$) плоскость персонажа развёрнута относительно камеры. Обычный плоский поворот `transform: rotate(θ deg)` вращает руку в плоскости экрана, создавая неестественное ощущение «картонного листа».

Для решения этой проблемы реализована система **проекции вращения конечностей**:
* **Автоматическое включение**: параметр `isIsometricRotation = true` включён по умолчанию в изометрическом режиме.
* **Режимы трансформации**:
  1. **Трапециевидная 3D-перспектива (`trapezoid`, по умолчанию)**:
     * Формула:
       $$\text{pitch} = \theta_{\text{tilt}} \cdot \sin(\text{rot}) \cdot (-1)^{\text{isFlipped}}$$
       $$\text{yaw} = -(\theta_{\text{tilt}} \cdot 0.5) \cdot \sin(\text{rot}) \cdot (-1)^{\text{isFlipped}}$$
       $$\text{transform} = \text{perspective}(500\text{px}) \cdot \text{rotateX}(\text{pitch}) \cdot \text{rotateY}(\text{yaw}) \cdot \text{rotateZ}(\text{rot})$$
     * При угле покоя ($\text{rot} = 0^\circ$) коэффициенты $\sin(0) = 0$, поэтому в нейтральной позе пиксель-арт остаётся кристально чётким без искажений.
     * При отведении плеча/руки деталь уходит в глубину экрана с перспективным трапециевидным сокращением, точно соответствующим изометрической глубине.
  2. **Аффинная диметрическая проекция (`dimetric`)**:
     * Моделирует вращение по эллипсу изометрической сетки через связку `rotate(rot) skewX(skew) scaleY(scaleY)`.
* **Тонкая настройка**:
  * Вкладка «Позирование и Анимации» содержит блок управления углом изометрии (`isometricTiltAngle`, по умолчанию `26.565°`).
  * Быстрые пресеты: **Классика 2:1 (`26.565°`)**, **Изометрия (`30°`)**, **Военная/Кавалер (`45°`)**.
  * Мгновенный тумблер `📐 Изометрический поворот суставов` в боковой панели и на холсте.

### 5. Интерактивный изометрический холст
* **Изометрический ромб (Isometric Diamond Grid)**: визуализирует опорный тайл сетки ($64 \times 32$) под ногами персонажа, помогая выравнивать точку касания пола.
* **Отражение по горизонтали (`⇄ Отразить`)**: разворачивает персонажа влево/вправо с автоматической инверсией осей перспективного наклона суставов.
* **Инспектор костей и пивотов**: перекрестия центров и круги вращения суставов работают идентично 2D-режиму, позволяя интерактивно кликать по частям тела изометрического персонажа.

## 12. Движок рендеринга Canvas 2D и динамическое суперсэмплирование

Для устранения артефактов DOM-иерархии (накопление процентных смещений и искажения вращения дочерних контейнеров) реализован специализированный Canvas 2D движок (`CharacterRigRenderer.js` и компонент `CharacterCanvas.vue`).

### 1. Архитектура сцены и плоский граф (Scene Graph)
* Иерархия деталей собирается в матричный граф трансформаций (`computeSceneGraph`):
  * Каждая часть тела позиционируется относительно своего родителя через аффинную 2D-матрицу.
  * Все спрайты отрисовываются в единый 2D-контекст холста, отсортированные по `zindex`.
  * Интерактивные клики и наведение (`hitTest`) вычисляются через обратную матрицу трансформации каждого узла, обеспечивая 100% точность попадания независимо от масштаба и поворота.

### 2. Динамическое суперсэмплирование (Supersampling Zoom)
* **Чёткость детальных спрайтов и крупных планов**: персонажи 2D-новеллы используют детализированные высококачественные спрайты высокого разрешения (2000px–4000px+). При зуме холста колёсиком мыши в студии или при кадрировании крупных планов (close-up лица) в сюжетных сценах движок использует адаптивный буфер и сглаживание высокого качества.
* **Динамический размер внутреннего буфера**:
  * Входной проп `zoom` передаёт текущую визуальную кратность увеличения (из `stageZoom` студии или сценарного кадрирования новеллы).
  * Если явный `zoom` не передан, компонент автоматически рассчитывает CSS-масштаб родительского контейнера через `getBoundingClientRect().width / container.clientWidth`.
  * Итоговый масштаб буфера `renderScale = dpr * effectiveZoom` рассчитывается с учётом физической плотности пикселей экрана (`window.devicePixelRatio`).
  * Физические размеры холста (`canvas.width`, `canvas.height`) динамически увеличиваются до 1:1 соответствия физическим пикселям монитора с запасом разрешения до 8192px:
    ```js
    const maxBufferDim = 8192 // Защита от переполнения VRAM с поддержкой ультра-зума
    const renderScale = Math.min(Math.max(1, dpr * effectiveZoom), maxScale)
    canvas.width = Math.round(width * renderScale)
    canvas.height = Math.round(height * renderScale)
    ```
* **Разделение режимов сглаживания (2D VN vs Изометрия)**:
  * **2D Новелла (`isIsometric = false`)**: включено сглаживание высокого качества (`ctx.imageSmoothingEnabled = true`, `ctx.imageSmoothingQuality = 'high'`), а для холста и слоёв персонажа задано свойство `image-rendering: auto`. Благодаря этому оригинальные высокодетализированные текстуры тела и лица при приближении сохраняют плавные гладкие контуры, не пикселявят и выглядят кристально чёткими на любых крупных планах.
  * **2.5D Изометрия (`isIsometric = true`)**: сглаживание отключено (`ctx.imageSmoothingEnabled = false`), включены свойства `image-rendering: pixelated; image-rendering: crisp-edges;`, сохраняя строгую попиксельную чёткость пиксель-арта без размытия.

### 3. Разделение биометрического масштаба и сценарного кадрирования
* **Биометрический размер (`values.json size`)**: отвечает за приведение спрайта персонажа к каноническому росту на линейке сцены (например, 158 см для Энри $\to$ `size: 1.324`). Отрисовывается внутри Canvas движка.
* **Сценарный зум (`step.scale` / `stepScale`)**: используется авторами новелл для кадрирования (полный рост $\to$ 1.0, портрет/лицо во весь экран $\to$ 2.0–2.5). Применяется как CSS-масштаб на родительском контейнере `.char` и передаётся в Canvas как `zoom` для динамического суперсэмплирования буфера.
* **Исключение двойного масштабирования**: контейнер `.char` в Canvas-режиме не дублирует внутренний биометрический коэффициент `size`, гарантируя корректные пропорции персонажей относительно друг друга.

## 13. Система взгляда, маскирование (Clipping Mask) и ракурс зрачков

### 1. Таргетинг взгляда (Eye Gaze Targeting)
* Смещение взгляда (через джойстик `EyeDirectionPad` или параметры `eyeOffset`) затрагивает **исключительно** глазные яблоки и зрачки (`eyeball-left`, `eyeball-right`, `pupil`).
* Голова (`head`), глазницы (`eyes`), веки и брови (`eyebrows`) остаются неподвижными.
* Поддерживается независимое управление левым и правым глазом (`eyeControlMode = 'independent'`).

### 2. Маскирование по непрозрачным границам родителя (`clipToParent`)
* Для предотвращения вылезания зрачков за пределы глазного яблока в `body.json` и `iso_body.json` предусмотрено свойство `"clipToParent": true` (настраивается чекбоксом в инспекторе рига).
* **Canvas 2D реализация**:
  * Отрисовка детали с `clipToParent` выполняется через вспомогательный внеэкранный холст (`clipCanvas`).
  * Родительский спрайт (например, склера глаза `eyes-back`) рендерится как альфа-маска.
  * С помощью `globalCompositeOperation = 'source-in'` дочерний спрайт (зрачок `eyeball-left`) отсекается строго по контуру видимых пикселей родителя с нулевым падением FPS.
  * При клике (`hitTest`) координаты курсора дополнительно валидируются в границах родителя, исключая ложные клики за пределами маски.

### 3. Ракурс и сжатие зрачков (Perspective Turn & Scale)
* Во вкладке «Эмоции и глаза» и в редакторе анимаций доступны бегунки:
  * **Размер зрачков (Pupil Scale)**: масштабирование от $0.2\times$ до $2.5\times$ с пресетами для отыгрыша эмоций ($0.5\times$ — подозрение/прищур, $1.0\times$ — норма, $1.4\times$ — удивление/испуг).
  * **Поворот по горизонтали (Yaw / Rotate Y)**: от $-85^\circ$ до $+85^\circ$. Вычисляет $\text{scaleX} = \text{scale} \cdot \cos(\text{angle})$, сжимая зрачок по ширине при взгляде вбок.
  * **Поворот по вертикали (Pitch / Rotate X)**: от $-85^\circ$ до $+85^\circ$. Вычисляет $\text{scaleY} = \text{scale} \cdot \cos(\text{angle})$, сжимая зрачок по высоте при взгляде вверх или вниз.

## 14. Студия одежды и экипировки (Equipment & Clothing Rigging Studio)

Интерактивная среда настройки составных спрайтов одежды и экипировки персонажей (`CharacterRigEquipmentPanel.vue` во вкладке **«👗 Одежда»**).

### 1. Каталог предметов и фильтры
* Доступен выбор любого предмета из глобальной базы игры (`src/renderer/public/data/items/equipment.json`).
* **Поиск**: по названию (`name`) и ID предмета (`id`).
* **Фильтры по частям тела и слотам (Чипсы)**:
  * `✨ Все`
  * `🪖 Голова` (`head`)
  * `🎭 Маска` (`mask`)
  * `📿 Шея` (`neck_1`, `neck-1`)
  * `👕 Торс` (`torso-1`, `torso-2`, `torso-3`)
  * `🩲 Бельё` (`underpants`)
  * `🧤 Руки` (`hands`)
  * `👖 Ноги` (`legs`, `legs-2`)
  * `👢 Ступни` (`feet`)
  * `⚔️ Оружие` (`weapon-hand-1`, `weapon-hand-2`, `weapon_off`)
* **Фильтры источника**:
  * «Вся база» — полный каталог игры;
  * «В гардеробе» — предметы, уже добавленные в `equipment.json` персонажа;
  * «На кукле» — предметы, отображаемые на холсте прямо сейчас.
* **Кастомные предметы**: кнопка `➕ Новый ID` позволяет зарегистрировать любой уникальный предмет, даже если его ещё нет в базе данных.

### 2. Конструктор слоев (Parts Builder)
Каждый предмет экипировки может состоять из нескольких составных слоёв, привязанных к разным костям скелета (например, футболка: `body`, `arm_left`, `arm_right`):
* **Привязка к кости (`parent`)**: динамический выпадающий список всех костей персонажа из `body.json` (`body`, `head`, `neck`, `arm_left`, `arm2_left`, `arm3_left` и т.д.).
* **Файл спрайта (`image`)**: автоматический селектор найденных файлов из `images/sprites/characters/{charId}/equipment/` и текстовое поле для прямого ввода пути с превью-миниатюрой.
* **Z-Index**: управление порядком наложения (базовый Z-Index предмета и локальный Z-Index конкретного слоя).
* **Смещение (`offset.x`, `offset.y`)**: ползунки и микро-степперы (`-1%`, `0%`, `+1%`) для точной подгонки посадки ткани на теле персонажа.
* Все изменения мгновенно перерисовываются на холсте Canvas 2D (`CharacterCanvas.vue`) и DOM-дереве (`RigPartNode.vue`).

### 3. Интерактивная примерка и тестирование в движении
* Кнопки **«👁️ Одеть всё»** и **«🚫 Раздеть»** позволяют быстро раздеть персонажа до базового тела либо примерить весь комплект.
* Кнопка-глазок у каждого предмета в списке позволяет примерять и комбинировать вещи по отдельности.
* При переключении во вкладку «Позирование и Анимации» или запуске анимаций (дыхание, махание рукой, кашель) вся надетая одежда двигается вместе с родительскими суставами благодаря матричному графу трансформаций.

### 4. Сохранение данных (`equipment.json`)
Кнопка **«💾 Сохранить equipment.json»** (в карточке инспектора и в верхней шапке студии) форматирует и записывает данные в:
`src/renderer/public/data/characters/[characterId]/equipment.json`
Файл сразу становится доступен в сюжетных сценах визуальной новеллы, Редакторе данных и тактических боях.
