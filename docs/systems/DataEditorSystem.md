# Редактор данных и Управление сущностями (Data Editor System)

Данный документ описывает CRUD-систему **«Редактор данных»** (Data Editor), доступную во вкладке «Тесты», и регламентирует структуры данных игровых сущностей и синхронизацию с файловой системой проекта.

---

## 1. Обзор и архитектура

Редактор данных предназначен для создания, просмотра, обновления и удаления (CRUD) игровых сущностей:
- **Персонажи (Characters)**
- **Классы (Classes)**
- **Фракции (Factions / Fractions)**
- **Расы (Races)**
- **Предметы (Items)**

Интерфейс доступен в Главном меню: **«Тесты» → «Редактор данных»** (`/test/data-editor`).

### Прямая синхронизация с файловой системой:
Все действия в редакторе (создание, редактирование, удаление) обращаются к файловой системе проекта через безопасный мост Electron IPC (`window.electronAPI.dataEditor`). Изменения немедленно перезаписывают соответствующие `.json` файлы с форматированием `indent: 2`.

## 3. Схемы и ключи сущностей (JSON Schemas)

### 3.1. Персонажи (`Characters`)
*Файл:* `src/renderer/public/data/characters/{id}/values.json` *(реестр всех персонажей: `characters/characters.json`)*
```json
{
  "id": "momonga",
  "name": "Момонга",
  "names": ["Аинз Оал Гоун", "Владыка Назарика"],
  "gender": "male",
  "height": 177,
  "weight": 0,
  "age": "Нежить",
  "blood_type": "Отсутствует (Нежить)",
  "body_build": "Скелетное (Нежить)",
  "hair_color": "Отсутствуют",
  "eye_color": "Красные огоньки в глазницах",
  "distinguishing_features": "Костяное лицо, мантия владыки",
  "biometry_notes": "Высший лич, не имеет плоти и внутренних органов.",
  "icon": "images/sprites/characters/momonga/icometric/char.png",
  "races": ["overlord", "sceleton"],
  "classs": ["overlord", "mage"],
  "fractions": ["ainz-ooal-gown", "nazarick", "sorcerer-kingdom"],
  "tags": ["nazarick-leader", "supreme-being", "undead", "guildmaster"],
  "talents": ["item_restriction_bypass"],
  "description": "Глава гильдии Аинз Оал Гоун и верховный правитель Великой Гробницы Назарик."
}
```
> [!NOTE]
> - **Файловая изоляция персонажей**: Каждый герой хранится в отдельной директории `data/characters/{id}/`:
>   - `values.json` — ключевые метаданные (имя, пол, рост, возраст, вес, биометрия, расы, классы, фракции, теги, таланты, статы).
>   - `body.json` — анатомия, слоты кастомизации и спрайты.
>   - `equipment.json` — текущее снаряжение персонажа.
>   При сохранении персонажа в редакторе автоматически обновляется реестр `characters/characters.json` и генерируются базовые `body.json` / `equipment.json` (если отсутствуют). При удалении персонажа удаляется его папка.
> - **Пол персонажа (`gender`)**: поле обязательное и принимает одно из четырёх значений:
>   - `male` — 👨 Мужской
>   - `female` — 👩 Женский
>   - `genderless` — ⚪ Бесполый
>   - `hermaphrodite` — ⚧ Гермафродит
>   В карточке и форме персонажа выбор осуществляется с помощью интерактивного селектора с иконками.
> - **Связи с сущностями**: У персонажа может быть **несколько рас**, **несколько классов** и **несколько фракций**. В UI выбор осуществляется через интерактивные кнопки-чипсы (multi-select). Все связи хранятся в виде массивов строковых `id`.
> - **Подвкладки персонажа в редакторе (Character Sub-tabs)**:
>   В карточке редактирования персонажа доступно 6 специализированных подвкладок и кнопка быстрого перехода в Студию спрайтов (`🎭 Студия спрайтов →`):
>   1. **«👤 Основное»**: ID, имя, синонимы, пол, фракции, описание, теги, кастомные JSON-поля, а также компактные обзорные карточки биометрии, рас, классов и талантов с быстрым переходом в их вкладки.
>   2. **«📏 Биометрия» (`CharacterBiometricsTab.vue`)**:
>      - Баннер быстрого перехода в Студию спрайтов и риггинга (`/test/character-sprites?character={id}`).
>      - **Основные параметры тела**: Пол (`gender`), Рост (`height`, см), Вес (`weight`, кг), Возраст (`age`, лет / строка), а также инфо-плашка текущего скейла визуала (`size`).
>      - **Анатомия и физиология**: Группа крови (`blood_type`), Телосложение (`body_build`), Цвет волос (`hair_color`), Цвет глаз (`eye_color`), Особые приметы (`distinguishing_features`).
>      - **Биографические и медицинские заметки**: Текстовое поле `biometry_notes`.
>   3. **«🎒 Экипировка и Инвентарь» (`CharacterEquipmentTab.vue`)**:
>      - Унифицированная визуальная сетка квадратных слотов в стиле игрового инвентаря (`inventory.css`).
>      - Живой интерактивный аватар персонажа (`Character.vue`), отрисовывающий слои спрайтов из `body.json` и надетые предметы (`equipment.json`) в реальном времени.
>      - 4-колоночная сетка квадратных слотов экипировки (12 канонических слотов: `head`, `mask`, `neck_1`, `torso-1`, `torso-2`, `torso-3`, `hands`, `legs-2`, `feet`, `weapon-hand-1`, `weapon-hand-2`, `underpants`) с бейджами редкости, иконками типов и кнопками быстрого снятия/замены.
>      - Сетка инвентаря персонажа в виде квадратных ячеек (иконка, название, бейдж количества `xN`, индикатор экипировки/ограничений) с автозаполнением пустыми слотами.
>      - Инспектор выделенного предмета с деталями, характеристиками, счетчиком стака (`+`/`-`), кнопкой экипировки в подходящий слот и удалением. Поддержка быстрого надевания по двойному клику.
>      - Модальный выбор совместимых предметов для каждого слота и глобальный каталог добавления предметов.
>   4. **«🌟 Таланты» (`CharacterTalentsTab.vue`)**:
>      - Выделенная вкладка управления врождёнными талантами персонажа (`character.talents`).
>      - Каталог талантов из `skills/talents/talents.json` с поиском, фильтрами (все/выбранные/доступные) и бейджами механик.
>      - Переключение выбора талантов в 1 клик с отображением счетчика.
>   5. **«⚔️ Классы и навыки» (`CharacterSkillsTab.vue`)**:
>      - Иерархическое древо добавления классов персонажа (базовые, высшие, редкие классы с отображением родительских связей) прямо во вкладке.
>      - Управление уровнем конкретного класса (`character.class_levels[id]`) и SP персонажа.
>      - Унифицированный интерактивный холст древа навыков **`SkillTreeCanvas.vue`** (идентичен тестеру меню «Древо навыков и прокачки» `SkillTreeTesterView.vue`):
>        - Восходящая уровневая иерархия (Bottom-up: Уровень 1 внизу, высшие уровни поднимаются вверх).
>        - Пунктирные разделители уровней (`level-dashed-divider`) с бейджами статуса и интерактивной кнопкой открытия следующего уровня.
>        - Квадратные плитки навыков (4.8em × 4.8em) с цветными рамками и свечением категории, иконкой категории, большой иконкой, кружком изученности `✔`, названием под плиткой и бейджем стоимости.
>        - Плавные SVG-кривые Безье со стрелками `#arrow-learned`, `#arrow-available`, `#arrow-locked` и поддержкой связей ALL/ANY.
>        - Панорамирование перетаскиванием (drag-to-pan) и зум колесиком мыши + кнопки `−`, `100%`, `+`, `🎯 Центр`.
>        - Выдвижной инспектор навыка справа (`skill-inspector-panel`) с проверкой условий, описанием, JSON-данными, прокачкой рангов и забыванием.
>        - Тумблер строгого контроля требований и свободного режима GM (`isStrictMode`).
>   6. **«🧬 Расы и навыки» (`CharacterSkillsTab.vue`)**:
>      - Иерархическое древо добавления рас персонажа (гетероморфы, полулюди, гуманоиды).
>      - Управление расовым уровнем (`character.race_levels[id]`).
>      - Тот же унифицированный холст **`SkillTreeCanvas.vue`** с восходящими уровнями, SVG-связями, квадратными плитками и боковым инспектором.

### 3.2. Классы (`Classes`)
*Файл:* `src/renderer/public/data/classes/classes.json`
```json
{
  "id": "paladin",
  "name": "Паладин",
  "icon": "🛡️",
  "parent_id": "knight",
  "category": "combat",
  "tier": "rare",
  "tags": ["melee", "holy", "tank", "support"],
  "lvl_min": 5,
  "description": "Священный рыцарь, сочетающий боевое искусство со светлой магией исцеления и защиты."
}
```
- `parent_id` — идентификатор базового класса для специализаций (например, Воин → Рыцарь → Паладин). Для базовых классов равен `null`.
- `category` — категория класса:
  - `combat` — ⚔️ Боевые
  - `social` — 👑 Социальные
  - `craft` — 🔨 Ремесленные
  > [!IMPORTANT]
  > **Правило автонаследования категории**: Если у класса или расы указан `parent_id`, его категория автоматически и принудительно наследуется от родителя (`locked`). Ручная смена категории блокируется в интерфейсе, пока задан родитель. При изменении категории у родителя все его дочерние специализации каскадно обновляют свою категорию.

### 3.3. Фракции (`Factions`)
*Файл:* `src/renderer/public/data/fractions/fractions.json`
```json
{
  "id": "nazarick",
  "name": "Великая Гробница Назарик",
  "icon": "🏰",
  "type": "stronghold",
  "parent_id": "ainz-ooal-gown",
  "grid_tier": 1,
  "tags": ["dungeon", "headquarters", "sacred"],
  "description": "Неприступная подземная база гильдии из 10 этажей, населённая преданными НИП и монстрами."
}
```
- `type` — тип организации (`nation`, `guild`, `clan`, `religious`, `faction`, `stronghold`, `settlement`, `syndicate`, `tribe`).
- `parent_id` — вышестоящая организация (для вассалов, отделов, отрядов или филиалов). Для суверенных организаций равен `null`.
- `grid_tier` — опциональное числовое поле ручного позиционирования узла по вертикальной сетке (0, 1, 2, ...). Если не задано, уровень рассчитывается автоматически по глубине предков.
- Поддерживает отображение в виде интерактивного древа связей (Tree Canvas) с разделением на кластеры верховных фракций и под-подразделений.

### 3.4. Расы (`Races`)
*Файл:* `src/renderer/public/data/races/races.json`
```json
{
  "id": "skeleton",
  "name": "Скелет",
  "icon": "💀",
  "parent_id": null,
  "family": "skeleton",
  "category": "heteromorphic",
  "tier": "basic",
  "tags": ["undead", "skeleton"],
  "lvl_min": 1,
  "skill_points_per_level": 1,
  "spell_points_per_level": 0,
  "description": "Останки павших воинов, поднятые тёмной некромантией. Не ведают страха, боли и усталости, неуязвимы к холоду и ядам."
}
```
- `family` — логическое семейство расы (например, `elf`, `dwarf`, `beastman`, `skeleton`, `elemental`, `beast`, `celestial`, `infernal`). Используется для группировки нескольких независимых веток и одиночных рас в единый кластер на интерактивном холсте древа (`ClassRaceTreeCanvas.vue`).
- `parent_id` — предок или список предков через запятую для гибридных/высших ступеней (например, `"blood-guard, vampire-bride"`, `"succubus, incubus, demon"`, `"pegasus, unicorn"`, `"elder-fire-elemental, magma-elemental"`). Линии связи в древе строятся от каждого указанного предка.
- `grid_tier` — опциональное числовое поле ручного позиционирования узла по вертикальной сетке рангов (0, 1, 2, ...). Если задано, узел принудительно размещается на этом уровне; если не задано, уровень рассчитывается автоматически по глубине предков (`calculateDepth`).
- `category` — расовая ветвь (`humanoid`, `demi-human`, `heteromorphic`).
- `tier` — ранг расы (`basic` I ступень до 15 ур., `advanced` II ступень до 10 ур., `rare` III ступень до 5 ур.).
- `skill_points_per_level`, `spell_points_per_level` — начисление очков навыков и заклинаний при повышении уровня.

### 3.5. Предметы (`Items`)
*Файлы:* `src/renderer/public/data/items/equipment.json` и `src/renderer/public/data/items/other.json`
```json
{
  "id": "sword-diamond",
  "name": "Алмазный меч",
  "type": "equipment",
  "slot": ["weapon-hand-1", "weapon-hand-2"],
  "sprite": "images/sprites/items/equipments/sword-diamond.png",
  "weight": 0.5,
  "stackable": false,
  "lvl": 5,
  "characters": ["mc", "momonga"],
  "genders": ["male"],
  "races": ["human", "overlord"],
  "classs": ["warrior", "paladin"],
  "tags": ["weapon", "melee"],
  "description": "Острый клинок из зачарованного алмаза."
}
```
- Для экипировки (`type: 'equipment'`) запись ведется в `equipment.json`.
- Для расходников и валюты (`type: 'other'`) запись ведется в `other.json`.

#### Ограничения экипировки и выбор слотов:
- **Выбор слотов (`slot`)**: предмет может подходить как в один слот (`"torso-1"`), так и в несколько слотов одновременно (например, одноручное оружие в `"slot": ["weapon-hand-1", "weapon-hand-2"]`). В интерфейсе редактора выбор осуществляется интерактивными кнопками-чипсами всех доступных слотов тела.
- **Минимальный уровень (`lvl` / `lvl_min`)**: числовое ограничение на уровень персонажа.
- **Ограничение по полу (`genders`)**: интерактивный выбор разрешённых полов (`male`, `female`, `genderless`, `hermaphrodite`).
  > [!IMPORTANT]
  > **Правило пропуска**: если список полов пуст или не указан, предмет разрешён **для всех полов**. В таком случае поле `genders` автоматически опускается при сохранении файла, чтобы не загромождать JSON.
- **Поисковый селектор тегов (`EntityTagPicker.vue`) для классов, рас и персонажей**:
  Чтобы не перегружать DOM и форму тысячами кнопок-чекбоксов, выбор разрешённых классов (`classs`), рас (`races`) и персонажей (`characters`), а также привязок в карточке персонажа (`races`, `classs`, `fractions`), реализован через теговый селектор с автодополнением:
  1. **Отображение только выбранных сущностей**: выбранные элементы выводятся в виде компактных цветных чипсов с иконкой, названием, ID и крестиком быстрого удаления `✕`.
  2. **Поле живого поиска**: поле ввода с иконкой `🔍` и выпадающим списком (autocomplete), фильтрующим варианты по ID и локализованному названию. Уже выбранные элементы автоматически исключаются из подсказок.
  3. **Навигация клавиатурой**: стрелки `↑` / `↓` для перемещения по списку, `Enter` для добавления, `Esc` для закрытия.
  4. **Состояние по умолчанию**: при отсутствии ограничений отображается аккуратная подсказка *«Разрешено любому классу (без ограничений)»*.
  5. **Кнопка сброса**: кнопка «✕ Сбросить (Все)» позволяет моментально очистить ограничения в 1 клик.
- **Правило компактного JSON (Clean JSON)**: пустые массивы ограничений (`characters: []`, `races: []`, `classs: []`, `genders: []`) автоматически удаляются из сохраняемого объекта JSON. В игре их отсутствие трактуется как «доступно всем без ограничений».

### 3.6. Теги и наследование тегов у Персонажей (`Tags`)
*Файл реестра:* `src/renderer/public/data/tags/tags.json`
Глобальный массив строк всех зарегистрированных тегов игры (`['melee', 'undead', 'magic', ...]`). В интерфейсе редактора доступна отдельная вкладка **«🏷️ Теги»** для создания новых тегов и инспекции их использования во всех сущностях.

#### Механика тегов персонажей:
1. **Собственные теги персонажа (`character.tags`)**:
   Индивидуальные теги конкретного героя (например, `gamer`, `protagonist`, `supreme-being`). Только они записываются в `characters/{id}/values.json`.
2. **Унаследованные теги**:
   Динамически подтягиваются в рантайме из выбранных рас (`character.races`), классов (`character.classs`) и фракций (`character.fractions`). В карточке отображаются с указанием источника: `[ 🧬 Нежить (раса) ]`, `[ ⚔️ Воин (класс) ]`, `[ 🏛️ Назарик (фракция) ]`.
3. **Итоговый сводный пул (Combined Tags)**:
   Вычисляется функцией `getCharacterCombinedTags(character)` как объединение без дубликатов (`Set([ownTags, inheritedTags])`). Используется боевой системой и сценарными условиями игры. **В файл JSON персонажа не сохраняется**, чтобы избежать дублирования и загрязнения исходных данных.

### 3.7. Редактор произвольных пользовательских полей JSON (Custom Fields JSON Editor)
Если в файлах JSON прописаны нестандартные или произвольные структуры (например, `points-per-lvl`, `baffes`, `effects`, `stats`, `custom_quest_id`, `drop_chance` и др.), в форме сущности доступен встроенный интерактивный редактор кода:
- **Интерактивный редактор кода**:
  - Полноценный текстовый редактор с моноширинным шрифтом (`monospace`), темной темой, стилизацией strictly в `em` и поддержкой табуляции клавишей `Tab` (вставка 2 пробелов).
  - Отображает все нестандартные свойства сущности в виде отформатированного JSON-объекта `{ "key": value }`.
- **Инструменты панели редактора**:
  - **«🪄 Форматировать JSON»**: автоматическое выравнивание отступов (`JSON.stringify(parsed, null, 2)`).
  - **«➕ Шаблон»**: вставка примера структуры пользовательских полей при создании или заполнении.
  - **«🗑️ Очистить»**: сброс всех пользовательских полей до пустого объекта `{}`.
- **Живая валидация синтаксиса и защита данных**:
  - При вводе каждого символа проверяется синтаксическая корректность JSON.
  - При ошибке синтаксиса выводится плашка с точным сообщением парсера (например: *«Ошибка синтаксиса JSON: Expected ':' after property name»*), а кнопка «💾 Сохранить в JSON» автоматически блокируется.
  - При коллизии с управляемыми полями (если пользователь попытается задать `id`, `name`, `tags` и др.) выводится предупреждение, защищающее основные поля от перезаписи.
- **Полноценное управление полями (Добавление, Изменение, Удаление)**:
  - Пользователь может добавлять новые поля, менять существующие значения и удалять ненужные ключи. При удалении ключа из редактора он безвозвратно удаляется из сохраняемого файла JSON.

### 3.8. Выпадающий селектор автодополнения тегов (Tag Autocomplete Dropdown)
В поле ввода тегов встроен живой поиск с подсказками:
- При вводе каждого символа снизу раскрывается список совпадений из глобального реестра `tags.json` с подсветкой совпадающих букв.
- Отображается счетчик частоты использования тега в проекте.
- Возможность мгновенного выбора кликом мыши или клавишами со стрелками `Вверх` / `Вниз` + `Enter`.
- Если введенного тега ещё нет в реестре, автоматически предлагается вариант `+ [новый тег]` с созданием и добавлением в `tags.json`.

### 3.9. Ручная сортировка и иерархия дочерних сущностей (Manual Sorting & Hierarchy Tree)
1. **Физический порядок в файле JSON**:
   - Порядок отображения элементов в списке редактора строго соответствует порядку объектов в массиве JSON-файла (`classes.json`, `races.json`, `fractions.json`, `characters/characters.json`, `tags.json`, `equipment.json`).
   - Каждая карточка снабжена индикатором позиции `#1`, `#2`, `#3`...
2. **Управление порядком (кнопки `▲` / `▼` и Drag-and-Drop)**:
   - Пользователь может кликнуть на стрелку `▲` (вверх) или `▼` (вниз), либо перетащить карточку мышью.
   - Изменение порядка немедленно перезаписывает JSON-файл на диске в новом порядке через IPC.
   - При активном текстовом поиске ручная сортировка временно блокируется во избежание нарушения порядка скрытых элементов.
3. **Размещение дочерних сущностей (Классы, Расы, Фракции)**:
   - Дочерние сущности (с заполненным `parent_id`) автоматически группируются строго под своей базовой/родительской сущностью в файле и интерфейсе.
   - В списке слева у дочерних элементов отображается боковой древовидный указатель: отступ `margin-left: 1.8em`, графическая ветка `↳`, цветная акцентная граница и бейдж (например: `↳ Дочерний класс от: Воин`, `↳ Подраса от: Скелет`, `↳ Подразделение: Аинз Оал Гоун`).
4. **Сохранение целостности ветвей при перемещении**:
   - При перемещении родительского элемента вверх или вниз перемещается весь блок (родитель вместе со всеми своими дочерними элементами), исключая отрыв детей от родителя.
   - Дочерние элементы одного родителя можно свободно менять местами между собой.

### 3.10. Локализация и разделение текстов по языкам (Localization & Separate Locale Files)
Для предотвращения разрастания и загромождения файлов игровых механик всеми языковыми переводами реализована строгая архитектура разделения данных:
1. **Единый источник переводов**:
   Все отображаемые строки (`name`, `description`, а для персонажей — массив синонимов `names`) хранятся в изолированных файлах локалей:
   ```text
   src/renderer/public/data/locales/{lang}/{type}.json
   ```
   где `{lang}` — код языка (`ru`, `en`), а `{type}` — тип сущности (`characters`, `classes`, `fractions`, `races`, `items`).
   Формат файла представляет собой словарь соответствий по `id`:
   ```json
   {
     "warrior": {
       "name": "Воин",
       "description": "Мастер ближнего боя..."
     },
     "paladin": {
       "name": "Паладин",
       "description": "Священный рыцарь..."
     }
   }
   ```
2. **Связь между сущностями и переводами**:
   Связь осуществляется строго по первичному ключу `id`. Основной файл механики (например `classes.json`) содержит только игровые характеристики и отношения (`parent_id`, `lvl_min`, `tags`, и т.д.), а также обратную совместимую копию имени для упрощения чтения.
3. **Правило дефолтного языка и каскадный Fallback**:
   - Русский язык (`ru`) является базовым системным языком по умолчанию.
   - Если для выбранного языка (например `en`) перевод отсутствует или поле пустое:
     1. Функция `getEntityText(type, id, field, lang)` автоматически обращается к русскому оригиналу (`ru`).
     2. Если перевод отсутствует и в русском файле, возвращается поле из самой сущности.
     3. Если отсутствует и оно, для `name` возвращается `id`.
   - В списке карточек у записей без перевода на выбранный язык отображается компактный индикатор `[RU]`, информирующий, что показывается русский оригинал.
4. **Интерфейс переводчика и управление языками в Редакторе данных**:
   - **Выпадающий селектор языков в шапке (Header Dropdown Switcher)**: компактная кнопка с флагом, названием, кодом (`[ 🇷🇺 Русский (RU) ▼ ]`) открывает выпадающее меню со списком всех активных языков, индикатором основного языка (`[Основной]`) и кнопкой `➕ Добавить язык...`. Закрывается по клику вне меню.
   - **Динамическое добавление новых языков (`addLocale`)**: модальное окно добавления локализации предлагает сетку готовых пресетов (🇯🇵 Японский `ja`, 🇨🇳 Китайский `zh`, 🇩🇪 Немецкий `de`, 🇪🇸 Испанский `es`, 🇫🇷 Французский `fr`, 🇰🇷 Корейский `ko`, 🇮🇹 Итальянский `it`, 🇵🇹 Португальский `pt`, 🇵🇱 Польский `pl`, 🇺🇦 Украинский `uk`, 🇹🇷 Турецкий `tr` и др.) или ручной ввод кода языка (ISO 639-1), названия и эмодзи-флага. При добавлении язык мгновенно регистрируется в реактивном пуле `availableLocales`, создаются пустые словари и переключается активный язык.
   - **Встроенная панель локализации в форме**: компактный выпадающий список `<select>` с быстрой кнопкой `➕ Добавить язык`, статусом перевода (`[Основной (Дефолт)]`, `[Нет перевода]`, `[Переведено]`), отображением оригинального русского текста в плейсхолдерах и всплывающих подсказках, а также блоком референсного русского описания для удобного составления переводов.
5. **Мультиязычный умный поиск**:
   Поисковая строка фильтрует сущности одновременно по русским, английским и любым добавленным языковым названиям, описаниям, синонимам и тегам независимо от того, какой язык сейчас выбран в интерфейсе.

### 3.12. Интерактивное древо классов, рас и фракций (Tree View Canvas)
На вкладках «Классы», «Расы» и «Фракции» в верхнем тулбаре доступен переключатель режимов:
- **`[ 🌳 Древо ]`** — визуальный граф специализаций, эволюций и субординации с ориентацией «Снизу Вверх».
- **`[ 📋 Список ]`** — традиционный список карточек с фильтрацией.

#### Возможности режима «Древо»:
1. **DOM + SVG (без canvas)**: Узлы построены на чистых Vue-компонентах с поддержкой всех CSS-стилей, тем и доступности. Соединительные линии отрисованы векторными кривыми Безье (`cubic bezier`) со стрелками направления от родителя (снизу) к потомку (вверху). Линия заканчивается точно под основанием стрелки (`endY = cY + arrowLength`, `refX="1"` у маркера), исключая протыкание острия толстым штрихом линии. Для изогнутых соединений перед стрелкой добавлен строго вертикальный подводящий отрезок (`lead-in` 10px), благодаря чему линия никогда не входит в стрелку сбоку. При вертикальном расположении узлов на одной оси линия отрисовывается идеально прямой. Слой SVG находится на `z-index: 3` (поверх полупрозрачного фона кластеров, что исключает эффект размытия от `backdrop-filter: blur`), а карточки узлов на `z-index: 4`.
2. **Панорамирование и свайп (Pan & Zoom)**:
   - Свободное перетаскивание холста (pan) зажатием ЛКМ по любой свободной области холста или средней кнопкой мыши с курсором `grab` / `grabbing`.
   - На время перетаскивания слушатели привязаны к `window`, что гарантирует плавное движение без срывов при быстром перемещении мыши.
   - Поддержка горизонтальной прокрутки при удержании `Shift + Wheel` и жестов тачпада.
   - Зуммирование от `0.45x` до `2.0x` колесиком (`Ctrl + Wheel`) или кнопками `+`, `−`, `100%`, `🎯 Центр`.
3. **Разделение под-веток и 2D Column-Slot Grid**:
   - Внутри семейного кластера сущности разделяются по независимым под-веткам от базовых корней.
   - Каждая под-ветка рассчитывает ширину своего поддерева (`calcSubtreeWidth`) и резервирует непрерывный диапазон колонок (`assignColumnSlots`). Родитель центрируется точно в диапазоне колонок своих дочерних узлов, а листовые элементы оставляют верхние ячейки свободными без перекрытия чужих веток.
4. **Ручное позиционирование по вертикали (`grid_tier`)**:
   - Позволяет в редакторе классов, рас и фракций вручную указать уровень в сетке (0, 1, 2, ...), если авторасчёт по предку не соответствует замыслу дизайнера.
5. **Группировка по категориям и нижняя панель кнопок**:
   - Кнопки переключения категорий расположены в нижней панели холста:
     - Для классов: `⚔️ Боевые`, `👑 Социальные`, `🔨 Ремесленные`, `🌐 Все`.
     - Для рас: `👤 Гуманоиды`, `🐾 Полулюди`, `💀 Гетероморфы`, `🌐 Все`.
     - Для фракций: `🌐 Все`, `👑 Государства`, `⚔️ Гильдии и ордена`, `🖐️ Кланы и синдикаты`, `☀️ Религии и культы`.
   - **Динамический фон (Mood Theme)**: При переключении вкладок фон плавно меняет оттенок (рубиновый, сапфировый, янтарный, изумрудный, фиолетовый, благородное королевское золото и др.).
6. **Квадратный узел в стиле скилов (Skill Tree Aesthetic)**:
   - Размер `4.8em × 4.8em` с крупной иконкой по центру.
   - В левом верхнем углу — римская цифра ранга/уровня (`I`, `II`, `III`, `IV`).
   - В правом нижнем углу — счетчик прямых подклассов/подразделений (`↳ X`).
   - Под квадратом — название сущности, ID, а для фракций также бейдж типа организации (`.node-type-pill`: Государство, Гильдия, Клан, Оплот и др.).
   - При наведении отображается тулбар быстрых действий: `✏️ Редактировать`, `➕ Создать дочернюю сущность`, `⚡ Древо навыков` (для классов и рас — мгновенный переход в тестер прокачки), `🗑️ Удалить`.
   - В форме сущностей классов и рас в блоке навыков добавлена кнопка `[ 🌳 В древо навыков → ]` для быстрого перехода к тестеру с выбранной сущностью.
   - Холст использует общие утилиты `treeConnectors.js` (построение кривых Безье со стыковкой с основанием стрелок) и композабл `useTreePanZoom.js` (панорамирование и масштабирование).
   - При клике на ноду справа плавно выдвигается боковая панель инспектора / редактирования формы (`.__tree-drawer`), не перекрывая обзор древа.
7. **Быстрое создание дочерней сущности**:
   - Клик по кнопке `➕` на узле открывает форму создания с предустановленным `parent_id` и унаследованной категорией/типом организации.

### 3.13. Режим выбора и переиспользуемый селектор древа (`ClassRaceTreeDrawer.vue`)
Для унификации интерфейса выбора классов и рас в карточке персонажа и других модулях редактора `ClassRaceTreeCanvas.vue` поддерживает режим выбора, а также обёрнут в переиспользуемый компонент-дровер `ClassRaceTreeDrawer.vue`:

1. **Режим выбора `selectionMode` в `ClassRaceTreeCanvas.vue`**:
   - **Пропсы**: `selectionMode: Boolean` (по умолчанию `false`) и `assignedIds: Array` (список ID уже назначенных сущностей).
   - **Индикация назначения**: узлы, входящие в `assignedIds`, получают класс `.__assigned`, изумрудную рамку, свечение и бейдж `✔` в углу квадрата.
   - **Скрытие CRUD-действий**: кнопки редактирования, удаления и создания дочерних элементов скрываются; вместо них при наведении отображаются кнопки `➕ Взять` / `✔ Снять` (`.node-selection-actions`).
   - **Событие `toggleAssign`**: клик по квадрату узла или по кнопкам действия генерирует событие `@toggle-assign(node)`, переключающее привязку сущности.

2. **Компонент-дровер `ClassRaceTreeDrawer.vue`**:
   - Полнофункциональный интерфейс-селектор со стилизованной шапкой (иконка сущности, заголовок, поясняющий текст, счётчик выбранных элементов и кнопка закрытия `✕ Закрыть древо`).
   - Включает в себя холст `ClassRaceTreeCanvas` в режиме `selectionMode` с поддержкой масштабирования, категорийных вкладок, поиска и локализации.
   - Поддерживает как блочное размещение в рабочей области (по умолчанию `height: 44em`), так и режим модального оверлея (`:overlay="true"`).

3. **Интеграция в карточку персонажа (`CharacterSkillsTab.vue`)**:
   - Полностью заменяет временный плоский список карточек на полноценное интерактивное древо классов и рас.
   - Кнопка `➕ Древо классов` / `➕ Древо рас` открывает `ClassRaceTreeDrawer`. Назначенные классы и расы сразу отображаются в чипсах персонажа с автоматической инициализацией уровня (`1`).

### 3.14. Табличный редактор в стиле Google Sheets (`DataTableEditor.vue`)
Для быстрого анализа, массового сравнения характеристик и редактирования сущностей классов, рас, фракций и предметов в шапку редактора добавлен режим **`[ 📊 Таблица ]`** (наряду с `[ 🌳 Древо ]` и `[ 📋 Список ]`).

#### Возможности табличного редактора:
1. **Сворачивание и группировка строк (Row Folding)**:
   - **Иерархия (Древо `tree`)**: Дочерние элементы (по `parent_id`) отображаются с древовидным отступом и графической ветвью `↳`. У родительских строк отображаются кнопки сворачивания `[−]` / `[+]`, скрывающие или раскрывающие всех потомков.
   - **Категории (`category`)**: Разделительные строки с иконками и бейджами категорий (например: `👤 Гуманоиды`, `🐺 Полулюди`, `💀 Гетероморфы`). Клик по строке-разделителю сворачивает/разворачивает всю категорию.
   - **Семейства (`family`)**: Группировка рас по семействам (`Люди`, `Эльфы`, `Гоблины`, `Нежить`).
   - **Плоский список (`flat`)**: Все записи выводятся на одном уровне с возможностью сортировки по любому столбцу (клик по заголовку: `▲` по возрастанию, `▼` по убыванию).
   - **Массовые действия**: Кнопки тулбара `➕ Развернуть все` и `➖ Свернуть все`.
2. **Сворачивание и управление колонками (Column Folding)**:
   - **Двухуровневая супер-шапка**: Столбцы сгруппированы в логические блоки:
     - **Основное (Core)**: Иконка, Название, ID, Категория, Семейство.
     - **Иерархия (Hierarchy)**: Базовый предок, Тир, Мин. уровень.
     - **Базовые характеристики (Base Stats)**: `HP`, `MP`, `Физ. Атака`, `Физ. Защита`, `Маг. Атака`, `Маг. Защита`, `Скор.`, `Иниц.`.
   - **Сворачивание групп (Compact Ribbon Strip)**: Каждая группа колонок снабжена кнопкой `[−]` / `[+]`. При нажатии на `[−]` группа мгновенно сжимается в узкую ленту (`2.2em`), текстовое название группы скрывается (остается только кнопка `[+]`), а в ячейках отображается компактный плейсхолдер `···`. Это позволяет быстро прятать громоздкие блоки колонок и освобождать горизонтальное пространство экрана.
   - **Скейлы характеристик (Converters — от 0 до множества параметров)**:
     - В колонках конвертеров (`STR`, `END`, `AGI`, `INT`) отображается реальная игровая модель скейлов: каждая характеристика может увеличивать от 0 до нескольких боевых параметров одновременно (например, `1 STR` $\to$ `+20 HP`, `+10 Физ.Атк`, `+8 Физ.Защ`, `+0.5% Крит.Урон`; `1 END` $\to$ `+35 HP`, `+10 Физ.Защ`, `+1% Физ.Сопр.`; `1 AGI` $\to$ `+0.2% Крит.Шанс`, `+0.1 Скор`; `1 INT` $\to$ `+20 MP`, `+10 Маг.Атк`, `+8 Маг.Защ`; или прочерк `—` при 0 параметров).
     - Поддерживаются параметры критического удара: **`Шанс крит. урона (%)`** (`crit_chance`, янтарный бейдж) и **`Крит. урон (%)`** (`crit_dmg`, коралловый бейдж).
     - Для всех процентных характеристик (`crit_chance`, `crit_dmg`, сопротивления `res.*`) и скейлов скорости шаг изменения числового инпута установлен в **`0.1`** (вместо целых 1%), что обеспечивает тонкую настройку баланса.
     - Параметры выводятся в виде цветных бейджей-чипсов (`.dte-conv-pill`) с цветовой кодировкой (`HP` — красный, `MP` — синий, `Физ.Атака` — оранжевый, `Физ.Защита` — стальной, `Магия` — фиолетовый/розовый, `Скорость/Инициатива` — зеленый/желтый, `Крит.Шанс` — золотистый, `Крит.Урон` — коралловый, `Сопротивления` — бирюзовый).
     - Кнопка `⚙️` открывает модальное окно настройки скейлов: добавление любого боевого параметра или сопротивления (`res.*`) из списка с иконками, редактирование коэффициентов с шагом 0.1 для процентов, удаление `🗑️` и кнопка быстрой очистки «Очистить все (0 параметров)».
   - **Меню видимости `👁️ Колонки`**: Выпадающий список чекбоксов для точечного включения/отключения любых колонок и быстрые пресеты: `Все`, `Статы`, `Скейлы`, `Компактно`.
3. **Цветовое оформление по спецификации**:
   - Темная/черная контрастная шапка (`#000000` / `#090d16`) с четкими белыми подписями.
   - Цветовая дифференциация категорий:
     - `humanoid`: синий бейдж (`#2563eb`) и мягкая подсветка ячеек.
     - `demi-human`: зеленый бейдж (`#16a34a`) и мягкая подсветка ячеек.
     - `heteromorphic`: маджента/красный бейдж (`#be185d`) и мягкая подсветка ячеек.
   - Подсветка колонок базовых статов глубоким синим оттенком (`rgba(59, 130, 246, 0.08)` / `#0e1e3e`).
4. **Редактирование ячеек по месту (In-Place Inline Editing)**:
   - Клик по ячейке выделяет её синей рамкой с квадратным маркером в правом нижнем углу (стиль Google Sheets).
   - Двойной клик (или `Enter`) переводит ячейку в режим редактирования:
     - Числовые поля: числовой ввод со стрелочками и валидацией `min`.
     - Категории / тиры / предки: выпадающий список `<select>`.
     - Текстовые поля: строковый инпут.
   - Измененные строки подсвечиваются янтарной полосой слева, а кнопка `💾 Сохранить (N)` в тулбаре отображает количество несохраненных сущностей и сохраняет их пакетом через `saveAllEntities()`.
5. **Интеграция с боковым инспектором (Split Drawer Mode)**:
   - Таблица занимает 100% ширины рабочей области при закрытом инспекторе.
   - При клике на кнопку `✏️` или строку справа плавно открывается боковой инспектор (`.__table-drawer`) для детальной настройки способностей, биометрии и тегов. При закрытии инспектора (`✕ Закрыть`) таблица снова расширяется на всю ширину.
6. **Управление фиксацией колонки действий (`📌 Закрепить действия`)**:
   - По умолчанию колонка «Действия» (✏️ 🗑️) скроллится вместе с таблицей как обычный столбец в конце строки, не прилипая к экрану.
   - Кнопка `📌` / `📍` в заголовке колонки «Действия» и в тулбаре позволяет в 1 клик зафиксировать колонку у правого края экрана (или открепить обратно).
   - При закреплении заголовок `<th>` и ячейки `<td>` прилипают строго синхронно с непрозрачным фоном, рамкой и тенью. Выбор сохраняется в `localStorage`.

## 4. Electron IPC API

В `src/main/index.js` и `src/preload/index.js` зарегистрированы IPC-каналы:
* `data-editor-get-info` — получение абсолютного пути к директории данных.
* `data-editor-read-file(relativePath)` — безопасное чтение и парсинг JSON с диска.
* `data-editor-write-file(relativePath, data)` — форматированная запись JSON на диск с созданием необходимых папок.
* `data-editor-delete-file(relativePath)` — удаление файла при необходимости.
* `data-editor-copy-locale(params)` — клонирование словарей и сценариев из языка-источника в новый язык и обновление `locales.json`.
* `data-editor-list-locales()` — получение списка всех установленных локалей со статистикой файлов.
* `data-editor-delete-locale(lang)` — удаление файлов локализации и очистка реестра `locales.json`.

Клиентские вызовы осуществляются через композаблы `useDataEditor.js` и `useLocalizationManager.js`:
```javascript
import { useDataEditor } from '@/composables/useDataEditor'
import { useLocalizationManager } from '@/composables/useLocalizationManager'

const { activeLocale, switchLocale, getEntityText } = useDataEditor()
const { installedLocales, createLocale, deleteLocale } = useLocalizationManager()
```

## 5. Правила верстки интерфейса редактора

1. Полноэкранный контейнер размещается внутри `#app` с `position: absolute; inset: 0;`.
2. Все размеры (padding, margin, gap, font-size, border-radius) заданы **строго в `em`**.
3. Использование `rem` и `px` (кроме hairline borders `1px solid`) запрещено правилами `AGENTS.md`.
