# Редактор данных и Управление сущностями (Data Editor System)

Данный документ описывает CRUD-систему **«Редактор данных»** (Data Editor), доступную во вкладке «Тесты», и регламентирует структуры данных игровых сущностей и синхронизацию с файловой системой проекта.

---

## 1. Обзор и архитектура

Редактор данных предназначен для создания, просмотра, обновления и удаления (CRUD) игровых сущностей:
- **Персонажи (Characters)**
- **Классы (Classes)**
- **Фракции (Factions / Fractions)**
- **Расы (Races)**
- **Предметы (Items)**

Интерфейс доступен в Главном меню: **«Тесты» → «Редактор данных»** (`/test/data-editor`).

### Прямая синхронизация с файловой системой:
Все действия в редакторе (создание, редактирование, удаление) обращаются к файловой системе проекта через безопасный мост Electron IPC (`window.electronAPI.dataEditor`). Изменения немедленно перезаписывают соответствующие `.json` файлы с форматированием `indent: 2`.

## 3. Схемы и ключи сущностей (JSON Schemas)

### 3.1. Персонажи (`Characters`)
*Файл:* `src/renderer/public/data/characters/characters_data.json`
```json
{
  "id": "momonga",
  "name": "Момонга",
  "names": ["Аинз Оал Гоун", "Владыка Назарика"],
  "icon": "images/sprites/characters/momonga/icometric/char.png",
  "races": ["overlord", "sceleton"],
  "classs": ["overlord", "mage"],
  "fractions": ["nazaric", "pnines-own-goal", "sorcerer-kingdom"],
  "tags": ["guildmaster", "undead", "supreme-being"],
  "description": "Глава гильдии Аинз Оал Гоун и верховный правитель Великой Гробницы Назарик."
}
```
> [!NOTE]
> У персонажа может быть **несколько рас**, **несколько классов** и **несколько фракций**. В UI выбор осуществляется через интерактивные кнопки-чипсы (multi-select). Все связи хранятся в виде массивов строковых `id`. При сохранении персонажей список их ID автоматически синхронизируется в реестре `characters/characters.json`.

### 3.2. Классы (`Classes`)
*Файл:* `src/renderer/public/data/classes/classes.json`
```json
{
  "id": "paladin",
  "name": "Паладин",
  "icon": "🛡️",
  "parent_id": "warrior",
  "tags": ["melee", "holy", "tank", "support"],
  "lvl_min": 5,
  "description": "Священный рыцарь, сочетающий боевое искусство со светлой магией исцеления и защиты."
}
```
- `parent_id` — идентификатор базового класса для специализаций (например, Воин → Паладин). Для базовых классов равен `null`.

### 3.3. Фракции (`Factions`)
*Файл:* `src/renderer/public/data/fractions/fractions.json`
```json
{
  "id": "nazaric",
  "name": "Великая Гробница Назарик",
  "icon": "🏰",
  "type": "stronghold",
  "parent_id": "pnines-own-goal",
  "tags": ["dungeon", "headquarters"],
  "description": "Неприступная подземная база гильдии, состоящая из 10 этажей."
}
```
- `type` — тип образования (`guild`, `nation`, `stronghold`, `settlement`, `clan`, `religious`).
- `parent_id` — вышестоящая организация (для вассалов или филиалов).

### 3.4. Расы (`Races`)
*Файл:* `src/renderer/public/data/races/races.json`
```json
{
  "id": "sceleton",
  "name": "Скелет",
  "icon": "🦴",
  "parent_id": "undead",
  "category": "heteromorphic",
  "tags": ["undead", "skeleton"],
  "lvl_min": 1,
  "description": "Оживлённый костяной остов, обладающий устойчивостью к колющему оружию."
}
```
- `category` — расовая ветвь (`humanoid`, `demi-human`, `heteromorphic`).
- `parent_id` — родительская раса (например: Нежить → Скелет → Повелитель).

### 3.5. Предметы (`Items`)
*Файлы:* `src/renderer/public/data/items/equipment.json` и `src/renderer/public/data/items/other.json`
```json
{
  "id": "sword-diamond",
  "name": "Алмазный меч",
  "type": "equipment",
  "slot": "weapon-hand-1",
  "sprite": "images/sprites/items/equipments/sword-diamond.png",
  "weight": 0.5,
  "stackable": false,
  "lvl": 5,
  "characters": ["mc", "momonga"],
  "races": ["human", "overlord"],
  "classs": ["warrior", "paladin"],
  "tags": ["weapon", "melee"],
  "description": "Острый клинок из зачарованного алмаза."

```
- Для экипировки (`type: 'equipment'`) запись ведется в `equipment.json`.
- Для расходников и валюты (`type: 'other'`) запись ведется в `other.json`.

### 3.6. Теги и наследование тегов у Персонажей (`Tags`)
*Файл реестра:* `src/renderer/public/data/tags/tags.json`
Глобальный массив строк всех зарегистрированных тегов игры (`['melee', 'undead', 'magic', ...]`). В интерфейсе редактора доступна отдельная вкладка **«🏷️ Теги»** для создания новых тегов и инспекции их использования во всех сущностях.

#### Механика тегов персонажей:
1. **Собственные теги персонажа (`character.tags`)**:
   Индивидуальные теги конкретного героя (например, `gamer`, `protagonist`, `supreme-being`). Только они записываются в `characters_data.json`.
2. **Унаследованные теги**:
   Динамически подтягиваются в рантайме из выбранных рас (`character.races`), классов (`character.classs`) и фракций (`character.fractions`). В карточке отображаются с указанием источника: `[ 🧬 Нежить (раса) ]`, `[ ⚔️ Воин (класс) ]`, `[ 🏛️ Назарик (фракция) ]`.
3. **Итоговый сводный пул (Combined Tags)**:
   Вычисляется функцией `getCharacterCombinedTags(character)` как объединение без дубликатов (`Set([ownTags, inheritedTags])`). Используется боевой системой и сценарными условиями игры. **В файл JSON персонажа не сохраняется**, чтобы избежать дублирования и загрязнения исходных данных.

### 3.7. Сохранение произвольных пользовательских полей JSON (Custom Fields Preservation)
Если в файлах JSON вручную прописаны дополнительные или вложенные поля, не предусмотренные стандартным интерфейсом (например, `points-per-lvl`, `baffes`, `effects`, `stats`, `custom_quest_id` и др.):
- **Они никогда не затираются**: При сохранении сущности через форму редактор выполняет мягкое объединение с оригинальным объектом (`mergedData = { ...baseItem, ...formData }`).
- **Инспектор в UI**: Если у редактируемой сущности обнаружены нестандартные поля, внизу формы автоматически отображается блок *«📦 Пользовательские поля из JSON: Сохраняются без изменений»* со списком найденных ключей и их значений.
- **Чистота данных**: Изменению подвергаются только те поля, которые были непосредственно отредактированы пользователем в интерфейсе.

### 3.8. Выпадающий селектор автодополнения тегов (Tag Autocomplete Dropdown)
В поле ввода тегов встроен живой поиск с подсказками:
- При вводе каждого символа снизу раскрывается список совпадений из глобального реестра `tags.json` с подсветкой совпадающих букв.
- Отображается счетчик частоты использования тега в проекте.
- Возможность мгновенного выбора кликом мыши или клавишами со стрелками `Вверх` / `Вниз` + `Enter`.
- Если введенного тега ещё нет в реестре, автоматически предлагается вариант `+ [новый тег]` с созданием и добавлением в `tags.json`.

### 3.9. Ручная сортировка и иерархия дочерних сущностей (Manual Sorting & Hierarchy Tree)
1. **Физический порядок в файле JSON**:
   - Порядок отображения элементов в списке редактора строго соответствует порядку объектов в массиве JSON-файла (`classes.json`, `races.json`, `fractions.json`, `characters_data.json`, `tags.json`, `equipment.json`).
   - Каждая карточка снабжена индикатором позиции `#1`, `#2`, `#3`...
2. **Управление порядком (кнопки `▲` / `▼` и Drag-and-Drop)**:
   - Пользователь может кликнуть на стрелку `▲` (вверх) или `▼` (вниз), либо перетащить карточку мышью.
   - Изменение порядка немедленно перезаписывает JSON-файл на диске в новом порядке через IPC.
   - При активном текстовом поиске ручная сортировка временно блокируется во избежание нарушения порядка скрытых элементов.
3. **Размещение дочерних сущностей (Классы, Расы, Фракции)**:
   - Дочерние сущности (с заполненным `parent_id`) автоматически группируются строго под своей базовой/родительской сущностью в файле и интерфейсе.
   - В списке слева у дочерних элементов отображается боковой древовидный указатель: отступ `margin-left: 1.8em`, графическая ветка `↳`, цветная акцентная граница и бейдж (например: `↳ Дочерний класс от: Воин`, `↳ Подраса от: Скелет`, `↳ Подразделение: Аинз Оал Гоун`).
4. **Сохранение целостности ветвей при перемещении**:
   - При перемещении родительского элемента вверх или вниз перемещается весь блок (родитель вместе со всеми своими дочерними элементами), исключая отрыв детей от родителя.
   - Дочерние элементы одного родителя можно свободно менять местами между собой.

### 3.10. Локализация и разделение текстов по языкам (Localization & Separate Locale Files)
Для предотвращения разрастания и загромождения файлов игровых механик всеми языковыми переводами реализована строгая архитектура разделения данных:
1. **Единый источник переводов**:
   Все отображаемые строки (`name`, `description`, а для персонажей — массив синонимов `names`) хранятся в изолированных файлах локалей:
   ```text
   src/renderer/public/data/locales/{lang}/{type}.json
   ```
   где `{lang}` — код языка (`ru`, `en`), а `{type}` — тип сущности (`characters`, `classes`, `fractions`, `races`, `items`).
   Формат файла представляет собой словарь соответствий по `id`:
   ```json
   {
     "warrior": {
       "name": "Воин",
       "description": "Мастер ближнего боя..."
     },
     "paladin": {
       "name": "Паладин",
       "description": "Священный рыцарь..."
     }
   }
   ```
2. **Связь между сущностями и переводами**:
   Связь осуществляется строго по первичному ключу `id`. Основной файл механики (например `classes.json`) содержит только игровые характеристики и отношения (`parent_id`, `lvl_min`, `tags`, и т.д.), а также обратную совместимую копию имени для упрощения чтения.
3. **Правило дефолтного языка и каскадный Fallback**:
   - Русский язык (`ru`) является базовым системным языком по умолчанию.
   - Если для выбранного языка (например `en`) перевод отсутствует или поле пустое:
     1. Функция `getEntityText(type, id, field, lang)` автоматически обращается к русскому оригиналу (`ru`).
     2. Если перевод отсутствует и в русском файле, возвращается поле из самой сущности.
     3. Если отсутствует и оно, для `name` возвращается `id`.
   - В списке карточек у записей без перевода на выбранный язык отображается компактный индикатор `[RU]`, информирующий, что показывается русский оригинал.
4. **Интерфейс переводчика и управление языками в Редакторе данных**:
   - **Выпадающий селектор языков в шапке (Header Dropdown Switcher)**: компактная кнопка с флагом, названием, кодом (`[ 🇷🇺 Русский (RU) ▼ ]`) открывает выпадающее меню со списком всех активных языков, индикатором основного языка (`[Основной]`) и кнопкой `➕ Добавить язык...`. Закрывается по клику вне меню.
   - **Динамическое добавление новых языков (`addLocale`)**: модальное окно добавления локализации предлагает сетку готовых пресетов (🇯🇵 Японский `ja`, 🇨🇳 Китайский `zh`, 🇩🇪 Немецкий `de`, 🇪🇸 Испанский `es`, 🇫🇷 Французский `fr`, 🇰🇷 Корейский `ko`, 🇮🇹 Итальянский `it`, 🇵🇹 Португальский `pt`, 🇵🇱 Польский `pl`, 🇺🇦 Украинский `uk`, 🇹🇷 Турецкий `tr` и др.) или ручной ввод кода языка (ISO 639-1), названия и эмодзи-флага. При добавлении язык мгновенно регистрируется в реактивном пуле `availableLocales`, создаются пустые словари и переключается активный язык.
   - **Встроенная панель локализации в форме**: компактный выпадающий список `<select>` с быстрой кнопкой `➕ Добавить язык`, статусом перевода (`[Основной (Дефолт)]`, `[Нет перевода]`, `[Переведено]`), отображением оригинального русского текста в плейсхолдерах и всплывающих подсказках, а также блоком референсного русского описания для удобного составления переводов.
5. **Мультиязычный умный поиск**:
   Поисковая строка фильтрует сущности одновременно по русским, английским и любым добавленным языковым названиям, описаниям, синонимам и тегам независимо от того, какой язык сейчас выбран в интерфейсе.

### 3.11. Инструмент «Добавить локализацию» (Localization Manager)
*Маршрут в приложении:* `/test/localization` (раздел «Тесты» в Главном меню).

Инструмент позволяет любому пользователю создать полноценный языковой пакет игры на базе дефолтного (русского `ru`) или любого другого языка:
1. **Клонирование дефолтного языка**:
   - Выбор источника копирования (по умолчанию `ru`).
   - Выбор целевого языка из пресетов (🇯🇵 `ja`, 🇨🇳 `zh`, 🇩🇪 `de`, 🇪🇸 `es`, 🇫🇷 `fr`, 🇰🇷 `ko` и др.) или ручной ввод (код ISO 639-1, название, эмодзи-флаг).
   - Выбор состава копирования:
     - **Словари сущностей**: копирует `characters.json`, `classes.json`, `fractions.json`, `races.json`, `items.json` в `locales/{targetCode}/`.
     - **Сюжетные сценарии**: рекурсивно копирует все сцены, диалоги и макросы из `story/{sourceCode}/` в `story/{targetCode}/`.
   - Регистрация в реестре `locales/locales.json`.
2. **Управление установленными языковыми пакетами**:
   - Карточки всех установленных локалей с бейджами статуса и счетчиками файлов словарей и сценариев.
   - Кнопка **«✏️ Редактировать в Редакторе данных»** — моментально открывает Редактор данных с этим активным языком для перевода сущностей.
   - Кнопка **«📋 Взять за основу»** — устанавливает выбранный язык как источник для нового клонирования.
   - Кнопка **«🗑️ Удалить»** — удаляет локализацию с диска (основной язык `ru` защищён от удаления).

## 4. Electron IPC API

В `src/main/index.js` и `src/preload/index.js` зарегистрированы IPC-каналы:
* `data-editor-get-info` — получение абсолютного пути к директории данных.
* `data-editor-read-file(relativePath)` — безопасное чтение и парсинг JSON с диска.
* `data-editor-write-file(relativePath, data)` — форматированная запись JSON на диск с созданием необходимых папок.
* `data-editor-delete-file(relativePath)` — удаление файла при необходимости.
* `data-editor-copy-locale(params)` — клонирование словарей и сценариев из языка-источника в новый язык и обновление `locales.json`.
* `data-editor-list-locales()` — получение списка всех установленных локалей со статистикой файлов.
* `data-editor-delete-locale(lang)` — удаление файлов локализации и очистка реестра `locales.json`.

Клиентские вызовы осуществляются через композаблы `useDataEditor.js` и `useLocalizationManager.js`:
```javascript
import { useDataEditor } from '@/composables/useDataEditor'
import { useLocalizationManager } from '@/composables/useLocalizationManager'

const { activeLocale, switchLocale, getEntityText } = useDataEditor()
const { installedLocales, createLocale, deleteLocale } = useLocalizationManager()
```

## 5. Правила верстки интерфейса редактора

1. Полноэкранный контейнер размещается внутри `#app` с `position: absolute; inset: 0;`.
2. Все размеры (padding, margin, gap, font-size, border-radius) заданы **строго в `em`**.
3. Использование `rem` и `px` (кроме hairline borders `1px solid`) запрещено правилами `AGENTS.md`.
