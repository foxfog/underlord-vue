# Система древа навыков и веток прокачки (Skill Tree System)

Данный документ описывает архитектуру системы древа навыков (Skill Trees) для **классов** и **рас**, уровневую сетку, логику предков (ALL/ANY), начисление очков уровня класса, списание и возврат очков прокачки (SP), а также интеграцию с Редактором данных и интерактивным тестером.

---

## 1. Концепция и ключевые правила

В соответствии с правилами прокачки в проекте Underlord-Vue:
1. **Каждый класс и каждая раса могут иметь свои ветки навыков** (`skill_branches`).
2. **Древовидная структура навыков «Снизу Вверх» (Bottom-to-Top)**:
   - Базовые навыки 0-го уровня располагаются в нижней строке дерева, а более продвинутые уровни поднимаются вверх.
   - Между родительскими и дочерними навыками строятся плавные соединительные кривые (SVG кубические кривые Безье).
   - Навык может не иметь предков вообще (`parent_ids: []`) — корневой навык тира.
   - Навык может иметь одного предка (`parent_ids: ["skill_a"]`).
   - Навык может иметь несколько предков (`parent_ids: ["skill_a", "skill_b"]`) с условием:
     - `parent_requirement: "all"` — для открытия должны быть изучены **все** предки (логическое И / AND, сплошная линия связи).
     - `parent_requirement: "any"` — для открытия достаточно изучить **хотя бы одного** из предков (логическое ИЛИ / OR, пунктирная линия связи).
3. **5 категорий способностей (`category`)**:
   - `active` — ⚔️ Активная способность (боевое умение, требующее активации в бою).
   - `passive` — 🛡️ Пассивная способность (постоянный эффект, бонус к защите или статам).
   - `aura` — ✨ Аура (постоянное воздействие на область вокруг или союзников).
   - `buff` — 🔼 Бафф (положительный эффект, временно повышающий характеристики).
   - `debuff` — 🔽 Дебафф (отрицательный эффект, накладываемый на цель).
4. **Равномерная ячеистая сетка и позиционирование (`grid_col`)**:
   - Каждая строка уровня имеет единое количество ячеек-слотов (`maxCols`).
   - Навык занимает определенную колонку (`grid_col`, начиная с 0).
   - В Редакторе данных навыки можно перемещать влево и вправо кнопками `◀` и `▶` (со свопом позиций с соседними навыками).
   - В пустых слотах доступно быстрое добавление нового навыка в нужную ячейку.
5. **Уровневая сетка и начисление очков уровня класса/расы**:
   - Каждый навык имеет требуемый уровень класса/расы (`req_level`, например 0, 1, 2...).
   - Каждый вложенный ранг навыка дает классу/расе фиксированное число очков уровня (`level_points_given`, по умолчанию 1).
   - Текущий уровень класса/расы персонажа вычисляется динамически:
     $$\text{ClassLevel} = \sum_{\text{skill} \in \text{LearnedSkills}} (\text{rank}(\text{skill}) \times \text{level\_points\_given}(\text{skill}))$$
   - Навыки 0-го уровня открыты сразу. Вкладывая очки в навыки 0-го уровня, игрок повышает уровень класса (например, до 1), что разблокирует навыки тира 1 (при выполнении требований их родителей).
6. **Очки прокачки (Skill Points / SP)**:
   - Прокачка любого ранга навыка расходует очки SP (`cost`, по умолчанию 1).
   - Поддерживается возврат очков (`refundSkill`) и полный сброс (`resetSkills`). Возврат отдельного навыка блокируется, если от него зависят уже изученные дочерние навыки или если снижение уровня класса сделает невалидными навыки старших тиров.
7. **Метаданные и произвольный JSON**:
   - Каждый навык содержит `id`, `name`, `icon` (emoji или путь к спрайту), `category`, `grid_col`, `description` и произвольное JSON-поле данных `data` (параметры урона, бонусы характеристик, кулдауны, стихии, формулы).

## 2. Архитектура файлов данных: двухуровневая система способностей

Для эффективного повторного использования способностей между классами, расами, предметами и талантами (например, навык «Ночное зрение» у Вора на 5-м уровне и врождённо у Квагота на 1-м уровне), система разделена на два взаимосвязанных слоя:

1. **Единый каталог способностей (`skills/skills.json`)**:
   - «Паспорт» каждого навыка: `id`, `name`, `icon`, `category`, `description`, произвольные данные `data` (формулы урона, эффекты, дальности).
   - Способности автономны и не привязаны жестко к классу или расе.
2. **Файлы деревьев прокачки сущностей (`skills/classes/<id>.json`, `skills/races/<id>.json`)**:
   - Содержат ветки (`skill_branches`) и компактные узлы-привязки (`skills`):
     - `skill_id`: ссылка на идентификатор из каталога `skills/skills.json`.
     - `branch`: ветка дерева.
     - `req_level`: требуемый уровень класса/расы (например, 1 для квагота, 5 для вора).
     - `grid_col`: позиция в сетке уровня.
     - `cost`: стоимость в очках прокачки (SP/MP).
     - `auto_unlock`: флаг врождённого/автоматического навыка (`true` — автоматически разблокируется при достижении `req_level` без списания SP).
     - `parent_ids` и `parent_requirement`: правила зависимостей («all» / «any»).
3. **Механика врождённых способностей (`auto_unlock: true`)**:
   - При получении уровня сущности (`levelUpEntity`) все навыки с `auto_unlock: true` и `req_level <= newLvl` автоматически активируются на 1-й ранг.
   - Очки SP/MP не списываются (`cost = 0`).
   - Сброс (`refundSkill`, `resetSkills`) блокируется для врождённых навыков — персонаж не может «забыть» свою врождённую расовую черту ради свободных SP.
4. **Бесшовный резолвинг в рантайме (`resolveSkillNode`, `resolveEntitySkills`)**:
   - При чтении деревьев утилита объединяет паспорт навыка из каталога с параметрами узла дерева.
   - Поддерживается полная обратная совместимость со старыми файлами, содержащими inline-поля `name`, `icon` и `description`.
5. **Файлы навыков предметов (`skills/items/items.json`) и талантов (`skills/talents/talents.json`)**:
   - Автономные реестры зачарований снаряжения и редких талантов Нового Мира.

### Пример каталога (`skills/skills.json`):
```json
{
  "id": "night_vision",
  "name": "Ночное зрение",
  "icon": "👁️",
  "category": "passive",
  "description": "Позволяет видеть в абсолютной темноте, нивелируя штрафы к меткости.",
  "data": { "darkness_immunity": true }
}
```

### Пример привязки узлов в дереве Квагота (`skills/races/quagoa.json`):
```json
{
  "skill_branches": [
    { "id": "quagoa_traits", "name": "Особенности квагоа", "icon": "⛏️" }
  ],
  "skills": [
    {
      "skill_id": "night_vision",
      "branch": "quagoa_traits",
      "grid_col": 0,
      "req_level": 1,
      "auto_unlock": true,
      "cost": 0,
      "parent_ids": []
    },
    {
      "skill_id": "night_vision_adv",
      "branch": "quagoa_traits",
      "grid_col": 0,
      "req_level": 3,
      "auto_unlock": false,
      "cost": 1,
      "parent_ids": ["night_vision"],
      "parent_requirement": "all"
    }
  ]
}
```

## 4. Унификация холста и соединений (Unified Tree Canvas)

1. **Единый стандарт стрелок (`treeConnectors.js`)**:
   - Маркеры стрелок используют единую конфигурацию `TREE_MARKER_CONFIG`: `refX="1"` (основание стрелки), `markerUnits="userSpaceOnUse"`, что гарантирует плотное примыкание линии к нижней кромке стрелки без протыкания острия.
   - Функция `buildBottomUpConnectorPath` обеспечивает строго вертикальные прямые линии между соосными узлами и вертикальный подводящий отрезок (`lead-in` 10px) для изогнутых линий, исключая боковой срез граней стрелки.
2. **Единое управление холстом (`useTreePanZoom.js`)**:
   - Холст навыков поддерживает панорамирование зажатием мыши (drag-to-pan) с курсорами `grab` / `grabbing`, зуммирование тулбаром (`+`, `-`, `100%`, `🎯 Центр`) и колесиком мыши (`Ctrl + Wheel` для зума, `Shift + Wheel` для горизонтальной прокрутки).
3. **Единый размер карточек узлов**:
   - Размер узлов унифицирован: `4.8em × 4.8em` (`.skill-square-box` и `.tree-node-square`), крупная иконка `1.85em` по центру, компактные бейджи по углам и двустрочные подписи под квадратом.

## 5. Архитектурные правила для ИИ-агентов

1. **Единицы верстки**: Все новые компоненты и стили обязаны использовать исключительно `em` и `%` (никаких `px`, `rem`, `vw`, `vh`).
2. **Безопасность сохранения JSON**: При сохранении классов и рас через `useDataEditor.js` пустые массивы `skill_branches` и `skills` автоматически удаляются, чтобы не загромождать сущности без настроенных навыков.
3. **Строгая валидация JSON**: Поле `data` в редакторе навыка парсится перед сохранением, гарантируя отсутствие синтаксических ошибок в файлах данных проекта.
